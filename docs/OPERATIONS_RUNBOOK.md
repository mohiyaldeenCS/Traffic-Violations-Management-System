# دليل التشغيل
## يوميًا
افحص /health/، معدل5xx وزمن p95، مساحة الأدلة والقاعدة، آخر نسخة احتياطية، تراكم outbox ومحاولاته.
نفذ `python manage.py verify_audit` وصَدّر رأس كل جهة إلى مستودع مراقبة مستقل في البنية المعتمدة.
`python manage.py dispatch_outbox` يسلّم inbox الداخلي فقط؛ لا يزعم إرسال SMS أو email.

## حادث سلامة دليل
أوقف إصدار القضايا المتأثرة، احفظ الأصل والlogs بصورة قراءة فقط، شغّل verify_audit وافحص بصمات النسخ الاحتياطية، عيّن مسؤول حادث. لا تعِد توليد hash لتطابق ملفًا تالفًا. أبلغ مالك البيانات وفق سياسة الجهة.

## حادث حساب
عطّل User.is_active عبر إجراء إداري موثق في قاعدة الإدارة؛ ألغ الجلسات المتأثرة. لا توجد واجهة تعطيل/reset لهذا الإصدار؛ يلزم إجراء two-person خارج التطبيق. المفتاح MFA يدور بإعادة تشفير منظمة ونسخة رجوع؛ فقده يستلزم إعادة تسجيل عوامل الهوية.

## نسخة واستعادة
استخدم pg_dump بصيغة custom، snapshot للأدلة الأصلية، مفتاح MFA وsecret في خزنة منفصلة، واتساق نقطة اللقطة بين القاعدة والملفات. نسخ مشفرة خارج الموقع، منع وصول التطبيق إليها.
اختبر restore إلى قاعدة جديدة منفصلة ثم verify_audit وقارن counts/hashes قبل تحويل حركة المرور. لا تنفذ pg_restore --clean على الإنتاج.
الأداة scripts/backup_restore.py تنفذ drill بقاعدتي مصدر وهدف منفصلتين وفارغة الهدف، ولا تلمس الأصل. تدعم PostgreSQL فقط.
الأهداف المقترحة RPO15m/RTO2h تحتاج WAL/PITR وخطة بنية وقياس دوري؛ لا تتحقق تلقائيًا من dump يدوي.

## تحديث
نسخة احتياطية → staging → migrations/check/tests → بناء immutable image → rollout تدريجي. فشل نسخة التطبيق: rollback image فقط إذا بقي schema متوافقًا؛ الترحيلات المدمرة تحتاج مرحلة expand/contract.
High Availability، tracing وتجميع logs مركزي وتنبيهات SIEM أعمال تشغيل لاحقة، لا يثبتها Docker Compose.
